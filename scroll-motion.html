展厅 C · SCROLL & PARALLAX

滚动与视差叙事

滚动是用户唯一自己掌握时间轴的交互。这一厅只做两件事：把滚动位移翻译成有意义的运动，以及在自建滚动容器里也不夺走键盘。

  • 10 个可交互 demo
  • 只用 transform / opacity
  • 内部滚动区全部键盘可用
  • 不使用 scroll-jacking
01揭示与视差 02滚动叙事 03滚动控制 04边界与取舍

01

揭示与视差

进入视口才出现，是为了让内容被"读完"而不是被"扫完"；错开是为了让眼睛有顺序。视差则只允许一个目的：制造深度。

01

滚动揭示（含 stagger）

进入视口 12% 时触发，6 个卡片按 45ms 逐张错开；可重播观察全过程。

01 触发阈值 12% 02 位移 16px 03 错开 45ms 04 只动 transform 05 只动 opacity 06 一次性

状态 已揭示 · 内核已扫描 0 个 .reveal / .stagger-seq 节点

触发
IntersectionObserver：threshold 0.12，rootMargin 0 0 -12% 0
时长
var(--dur-slower) 560ms；子项延迟 i × var(--stagger) 45ms
缓动
opacity var(--ease-out-quint)，位移 var(--ease-out-expo)
属性
opacity + transform: translate3d(0, 16px, 0) → 0
降级
lite/off：内核把位移换成纯淡入且 --stagger 归零，内容一次性出现、不丢信息

4 层视差

0.04 / 0.08 / 0.12 / 0.18 四层不同速率；右侧读数逐帧显示每层位移，可暂停对比。

L1 0.04 · L2 0.08 · L3 0.12 · L4 0.18

位移 0 / 0 / 0 / 0 px（相对视口中心）

触发
内核 ML.parallax()：document 上的 [data-parallax]，滚动时在 rAF 内统一写入
时长
无固定时长，直接跟随滚动位置（0ms 插值）
缓动
无（线性映射滚动位置 → 位移），避免二次缓动造成"水面漂移"

六个词各用不同速率横移，滚动时形成"透视滑动"的排版；关闭后立即回到规整基线。

滚动 不是 装饰 而是 阅读 的节拍

速率区间 0.04 – 0.19 · 共 6 段 · 状态 运行中

触发
同 demo 02（内核 ML.parallax），每个词一个 data-parallax 速率
时长
随滚动即时；入场词用 var(--dur-slower)
缓动
滚动映射无缓动；入场 var(--ease-out-expo)

02

滚动叙事

粘性堆叠、时间轴、章节变色——三种把"线性滚动"翻译成"章节感"的做法。它们全部在受限容器内运行，不会夺走页面的滚动条。

04

粘性堆叠卡片

卡片用 position: sticky 逐张盖上去，后一张压住前一张；内部滚动区可键盘操作。

01

收集

滚动位置换算成卡片堆叠顺序，不需要 JS 监听滚动。

02

分层

每张卡 top 递增 12px，视觉上像一叠纸被逐张压下。

03

交给用户

sticky 由浏览器合成，滚动条拖到哪儿，章节就停在哪儿。

04

收束

最后一张滚完后换成普通文档流，下一节自然出现。

容器滚动 0 px / 0 px · 当前可见卡片 1 / 4

触发
原生滚动容器（含滚轮 / 触摸 / 方向键 / PageUp·Down / 拖动滚动条）
时长
由滚动速度决定；卡片升起用 var(--dur-base) 240ms 的 transform
缓动
var(--ease-out-quint)（仅卡片自身的轻微缩放/抬升）
属性
transform: scale() / translate3d() + opacity（sticky 本身不产生动画）
降级
lite/off：卡片不再缩放抬升，sticky 行为保留（它是布局能力，不是动画）

03

滚动控制

进度条、吸附、横向轨道——三者共同的要求是：用户随时能停下来、能用键盘走完、能知道自己在哪儿。

07

分段滚动进度指示

读取根元素上的 --scroll-progress（内核逐帧写入），同时给出百分比、章节刻度和可点击的定位点。

页面进度 0% · 当前章节 — · 滚动位置 0 px

触发
页面 scroll（内核 ML.scroll.onScroll，rAF 节流）；刻度按钮走 ML.scroll.to
时长
进度条 0ms 跟手；点击定位 var(--dur-slower) 级别的平滑滚动
缓动
进度条无缓动（真实位置）；定位由浏览器原生 smooth 处理
属性
transform: scaleX(var(--scroll-progress))，transform-origin: left
降级
lite/off：定位变成瞬时跳转（HTML 的 scroll-behavior 由内核切到 auto）；百分比读数照常
08

scroll-snap 章节

强制吸附 vs 关闭吸附可实时对比；容器可聚焦，因此方向键、PageUp/Down、Home/End 全部可用。

第一屏 · 对齐肩线

scroll-snap-align: start，滚动停下时上边缘自动对齐。

第二屏 · 不做全屏劫持

高度固定为容器高度，但绝不锁定整页滚动。

第三屏 · 触摸惯性优先

proximity 让轻扫仍能连滚多屏，mandatory 会强制停靠。

第四屏 · 键盘同样对齐

方向键滚动后同样触发吸附，键盘用户体验一致。

当前屏 1 / 4 · scroll-snap-type y mandatory

触发
原生滚动 + scroll-snap-type；按钮调用 scrollTo 对齐，键盘走浏览器原生吸附
时长
吸附由浏览器合成器完成（约 200–400ms，不可也不应自定义）
缓动
浏览器原生；按钮触发时用 scroll-behavior: smooth
属性
scrollTop（浏览器合成层动画，不写 DOM 样式）
降级
lite/off：吸附本身不受动效档位影响（它是滚动行为）；关闭按钮随时可切回自由滚动
09

横向滚动区（键盘可用）

横向轨道带吸附与进度读数；左右按钮 + 方向键 + Home/End 三种走法都能到达每一项。

01

仅横向 scroll-snap

overflow-x: auto + scroll-snap-align: center。

02

不产生页面横向滚动

轨道自身 min-width: 0，overflow 只在轨道内。

03

键盘可达每一项

容器可聚焦后，方向键由浏览器原生处理。

04

按钮式兜底

触屏与鼠标用户用上一项 / 下一项按钮。

05

进度可读

刻度条显示当前位置，不只靠"还能不能滑"。

横向位置 0 / 0 px · 当前项 1 / 5

触发
原生横向滚动；按钮 scrollBy 一屏；方向键 / Home / End 由聚焦容器原生处理
时长
按钮滚动 var(--dur-slower) 级别（浏览器 smooth）
缓动
浏览器原生 smooth；无自定义曲线

scrollLeft（合成层）；卡片自身只用 transform / opacity

04

边界与取舍

这一节回答一个必须写进文档的问题：为什么全站不做 scroll-jacking。答案不是"不好看"，而是"它拿走了用户唯一完全掌握的东西"。

10

为什么不做 scroll-jacking（含反例对照）

左侧原生滚动、右侧用按钮触发的"接管"对照：接管期间你的输入会被丢弃，且全程可一键中止。

原生（本站在用）

滚动条跟着手指走。

键盘 Home / End / PageUp 原生可用。

触摸惯性由系统提供，帧率稳定。

锚点深链接、浏览器"回到上次位置"正常工作。

动效档位为 lite/off 时无需任何特殊处理。

接管（反例）

点击下面的按钮开始，然后试着用滚轮或方向键打断它。

接管状态 未接管 · 你的输入被丢弃 0 次

  • 输入延迟：接管用插值追赶目标，滚轮停下后画面还在动——这是"卡"的错觉，不是丝滑。
  • 可达性：键盘的 Home / End / PageUp 依赖原生滚动，接管后必须逐一重写，漏一个就断。
  • 无障碍：屏幕阅读器与"减少动态效果"用户最依赖原生滚动语义，接管会直接破坏它。
  • 成本：接管要自己处理触摸惯性、边界回弹、滚动条同步、移动端地址栏高度变化——全是风险。
  • 本站在用：锚点用 scroll-behavior: smooth，进度用 --scroll-progress，视差只在 rAF 内写 transform。
触发
按钮触发的 2.4s 示范（绝不监听滚轮，因此不会真的接管你的滚动）
时长
反例 2400ms（插值追赶）；原生侧无时长概念
缓动
反例用 ML.lerp 0.12/帧 —— 越接近目标越慢，正是"拖不动的感觉"来源
属性
反例写 scrollTop（会触发布局与合成，成本高于 transform）；原生侧浏览器自行调度
降级
lite/off：反例按钮直接跳到目标位置并说明「降级下不做插值」，对照结论不变
